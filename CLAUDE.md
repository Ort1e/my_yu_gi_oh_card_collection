# CLAUDE.md

Personal Yu-Gi-Oh! card collection manager: cards owned, purchase/sale lots, sellers,
monthly budget, decks (versions, categories, YDKE import/export, draw simulation), ban lists.
Plus a separate **book collection** (the owner's wife's novels: ISBN lookup and barcode scan,
authors, series, book advent calendars) under `/books`, and a **Pokémon card collection** (mostly
booster pulls, French/English/Japanese, wishlist, Cardmarket prices from TCGdex) under `/pokemon`.

## Goals — read first

What the app is for, in priority order (details and the usual tasks per goal: `docs/guide.md`):
1. **Manage the card collection** (main): cards, lots, sellers, budget, value, statistics, advent calendars, Pokémon. Menus **Collection** and **Pokémon**.
2. **Play competitively**: decks, the deck builder, built decks, formats, tournaments and their stats. Menus **Decks** (the bridge: the builder uses the collection and plans what to buy) and **Tournaments**.
3. **A public copy** to share: read-only static pages, no private data. Not a menu: a build (`export-public`).
4. **The books** (the owner's wife's novels). Menu **Books**.

### Where a feature goes (UI)
- **One function per page**, one place per action (a button, a panel, a wants list exists once; link to it from elsewhere, don't repeat it). Reading pages and data-entry forms are separate pages.
- Before adding a page or a panel, read `docs/guide.md`: put it under the goal's menu entry, and update the guide and `docs/tour.md` in the same commit.

## Division of work — read first

The port is finished; the project now serves as Rust practice for the owner, who wants to write the
**interesting functions and logic**, not the plumbing (owner's decision, 2026-10-19).
- **The owner implements the interesting logic**: algorithms and business rules, wherever they live
  (mostly `crates/yugioh-domain/`, also the core of a `store/` function or a command step), e.g.
  `single_rarity`, the valuation and its ownership-by-date, the built-deck locking rules, the
  Monte Carlo, a parser. Claude explains, reviews and proposes (signature, where it goes, similar
  code), and leaves a stub: signature, doc comment, `todo!()`, plus the unit tests it should pass.
- **Claude implements everything else**, backend included: migrations, SQL queries and `store/`
  writes, routes and handlers, forms, JSON APIs, commands' wiring and reports, background tasks,
  handler tests (`TestApp`), templates, CSS, the deck builder (`frontend/`), page scripts
  (`static/js/`), docs.
- When a feature is planned (spec), mark which functions are the owner's. When unsure whether a
  piece is "interesting logic" or plumbing, ask.
- **The books part** (`crates/books/`, `crates/books-domain/`, the book tables): Claude implements
  all of it, logic included (owner's decision, 2026-10-18).
- **The Pokémon part** (`crates/pokemon/`, `crates/pokemon-domain/`, the `pokemon_*` tables): Claude
  implements all of it, logic included, like the books (owner's decision, 2026-10-23).
- **The shared crates** (`common`, `common-domain`, `advent`) are plumbing (Claude), except a
  Yu-Gi-Oh! rule moved there (`common-domain`'s condition factors stay the owner's).

## Commands

All inside the Nix shell (`nix develop`, or automatic with direnv). Run from the **repo root** (relative paths: `static/`, `data/app.db`, `data/media`).

```bash
cargo check --workspace
cargo test --workspace
cargo clippy --workspace --all-targets
cargo cov                                     # test coverage → target/llvm-cov/html/index.html (alias in .cargo/config.toml; cargo llvm-cov --workspace --summary-only for a table)
cargo test -p yugioh-domain --test real_shipments -- --ignored --nocapture   # parser vs the real PDFs (prints counts/lot ids only)
cargo test -p yugioh                          # one crate's tests (also: books, pokemon, advent, common, backend, *-domain)

cargo run -p backend                          # web server, http://127.0.0.1:3000; runs migrations on startup
cargo run -p backend -- scrap-ban-list        # import new/current Konami ban lists, EU JSON then US pages for missing dates (--all, --dry-run, --date YYYY-MM-DD for a US list not linked yet)
cargo run -p backend -- clean-cards           # normalise names, relink card data, rarity from (V.x - …) names, names in their code's language, rarity of single-rarity codes from card data (--dry-run); the server also runs it in the background (5 min after start, then daily)
cargo run -p backend -- find-pictures         # give the cards their printing's picture from Yugipedia when there is no doubt (one artwork for their code, language, rarity); lists those to choose by hand (--dry-run: cached galleries only); new cards get theirs after their linking (`yugipedia::find_pictures`), so this is for the cards added before and the scans Yugipedia adds later
cargo run -p backend -- import-tournament-notes <file.json>   # one-off: the tournaments' old notes, transcribed, as rounds and games (--dry-run)
cargo run -p backend -- refresh-prices        # today's market prices: ygoprodeck into card_price, then Cardmarket's price guide (links, prices), then the Pokémon cards from TCGdex, then the Pokémon boosters from Cardmarket's catalogue (--dry-run); the server does it weekly by itself
cargo run -p backend -- export-public         # the public copy (static pages: Yu-Gi-Oh! and Pokémon cards, statistics, the public decks, the tournaments (no old notes), Pokémon wishlist, books, market values; nothing else) into public-export/ (--out DIR), for the OVH hosting: the app's own public pages crawled in-process (`common::export::write_site`, the addresses in `backend/src/commands/export.rs`), private parts left out by `{% if !common::export::public_copy() %}` in the templates
cargo run -p backend -- backup --to DIR      # consistent copy while the server runs: DIR/app-DATE.db (VACUUM INTO), media mirrored, --keep 14 days (the NAS runs it nightly)
backend fetch-release --to DIR                # on the NAS only: downloads the CI's `nas-latest` build when new (public release; GITHUB_TOKEN only for a private repository; deploy/nas/update.sh)
cargo run -p backend -- clean-pictures        # delete the cached card pictures (media/card_images, media/pokemon_card_images) no card uses any more (--dry-run); the server does it daily

DATABASE_URL=sqlite:/tmp/test.db cargo run -p importer -- data/data.json   # import the Django dump into a scratch DB (never over data/app.db)

cd frontend && npm install && npm run build   # → static/deck-builder/, needed by /deck-builder/:id
cd frontend && npm run check                  # TypeScript: svelte-check (deck builder) + tsc on static/js/ (JSDoc); the CI runs it
cd frontend && npm run dev                    # hot reload at http://localhost:5173/?id=<deck version id>, proxies to :3000
```

`.env` sets `DATABASE_URL=sqlite:data/app.db` (the default too). Both binaries create the DB file if missing.
`data/app.db` is **real data tracked in git** (the NAS's latest copy): don't delete/rebuild it, and don't run tests or experiments against it (use a scratch DB). The server closes the pool on Ctrl-C/SIGTERM (graceful shutdown), which checkpoints the WAL into `app.db`. The submodule is updated from the NAS by `deploy/pc/pull-backup.sh` (never commit a local server's changes to it).
Backend env vars (defaults): `BIND_ADDR` (`127.0.0.1:3000`), `APP_PASSWORD` (user `owner`, changes everything) and `APP_PASSWORD_<NAME>` (more users, who change only the books unless `APP_ACCESS_<NAME>` = `all` or a list `books,pokemon`; none = login disabled, then only a loopback `BIND_ADDR` is accepted), `PUBLIC_READS` (`1`; `0` = every page behind the login), `SECURE_COOKIES` (`0`; `1` behind HTTPS), `MEDIA_DIR` (`data/media`), `UPLOADS_DIR` (`uploads`, gitignored), `CARDMARKET_ACCOUNT` (`0rtie`), `GOOGLE_BOOKS_API_KEY` (none; in `.env` / the NAS's `collection.env`, never logged: reqwest errors `without_url()`). The work goes on `dev` (CI: `.github/workflows/ci.yml`), `main` = what runs (the NAS installs each new build of `main` at night). Pull requests `dev` → `main` are **rare**: several tested changes at a time, not one per change (owner's decision, 2026-10-28).

- Tables of data: one convention for all (`static/css/style.css`, "Data tables": `table.numbers` in `.table-scroll`, unit in the heading, `.text` columns, `sortable` + `static/js/tables.js` for sorting and search). The lot page groups the same copies on one row (`routes/lots/mod.rs`, `CopyGroup`).
- Phones: every page is responsive (`@media (max-width: 760px)` at the end of each stylesheet; header not fixed there). The deck builder is desktop-only. Phone access: docs/guide.md, "From a phone".
- Edition: `/{cards,sellers,lots,decks}/:id/edit` (GET form, POST save); `POST /decks/:id/delete` (versions cascade, a built one's copies freed), `POST /decks/:id/versions` (new version, `start` = `empty` / `copy:<version id>` / `ydke` → deck builder). `/deck-versions/:id` is the read-only view; `/decks/:id` is the hub (versions table); the builder (`/deck-builder/:id`, tabs Build / Missing / Test draw / Settings in `location.hash`) does all the editing.
- **Cards, unites, lots and sellers are never deleted** (they are the collection's history): no delete routes for them. Deck versions are edited/deleted only in the deck builder.
- `/card-image/:card_data_id` serves `media/card_images/<name>.jpg`, downloading it once from the URL in `card_data.json_data` if missing. `/card-picture/:name` serves a printing's picture (one address per picture, shared by its copies: once in the public copy) (`card.picture`, Yugipedia) from `media/card_pictures/` (JPEG, downloaded once, by `find_pictures` before it sets one; ygoprodeck's picture when it can't be had; downloads one every 2 s, 429 waited for: never let a page or the export start hundreds); `/cards/:id/pictures/:n` (login) the edit page's choices, `/cards/:id/edit?pictures=1` asks Yugipedia for the gallery. Pictures go through `store::models::picture_url`. `/static`, `/media` are plain file servers, except `/media/shipment_files`, `/media/advent_calendar_photos` and `/media/book_advent_calendar_photos` (login required: each crate's `Routes::private_media`, served by `common::app`).
- Login (`common::web::auth`, docs/tour.md "Login"): users from `APP_PASSWORD[_<NAME>]`, 5 wrong passwords → 15 min refusal, security headers on every answer (`web::headers`); with a password set, every collection's `write` and `private` routes and the private media folders (everything with `PUBLIC_READS=0`) need the session cookie: pages redirect to `/login?next=…`, `/api/*`, `/books/api/*` and `/pokemon/api/*` answer 401 `{"error": …}`. Reads stay public. New write routes must go in `write_router()` (Yu-Gi-Oh!) or `write` of the crate's `routes()`: there they also get `auth::require_access` (the user may change that collection: `Routes::collection`).
- Lot creation: `POST /lots/add/shipment` parses a Cardmarket PDF and re-renders the form pre-filled; the PDF waits as `uploads/pending-<token>.pdf` (deleted after 24 h) and moves to `media/shipment_files/shipment_<lot id>.pdf` on save. New cards are linked to card data by a background task, which then puts English names of cards coded in another language (`-FR`) in that language (ygoprodeck; recent sets may have no translation yet). The decks need nothing: a list sees a new copy as owned at once.
- `GET /api/sets/:code` (`routes/reference/sets.rs`): the cards of a set for the quick-add panel (ygoprodeck, cached; see docs/tour.md, "Talking to ygoprodeck").
- Deck builder API (`routes/decks/api/`): `/api/deck-versions/:id` `GET`/`PATCH`/`DELETE`, `…/clone`, `…/reserve` (the card search: owned cards, and by name the known ones, with their counts), `…/lookup` ("+ Card by name": a tile, nothing saved), `…/take-free` (a built version's empty slots take free copies), `…/categories[/:category_id]`, `…/cards/:card_data_id/categories[/:category_id]`, `…/monte-carlo` (optional `main`: a card data id per tile, the unsaved zones), `…/history` (the deck's snapshots; `…/history/:snapshot_id/name` names one), `…/compare` (a snapshot vs the zones on the screen), `…/check` (its problems in its format, as saved), and `/api/decks/:id/import-ydke`. The `PATCH` takes `ban_list_id` or `format_id` (both refused; cards' `ban` keys: `"12"` a list, `"f3"` a format, and `first_release`), also `is_public`, builds/unbuilds (`is_built`, answer with `build_report`; saving a built version's zones takes its new cards from the other versions the same way) and notes `deck_box`/`sleeves`. A version's zones go and come as tiles (one per copy: `ApiCard`, `CardInput`), stored as lines (`store::lists`). Zone edits stay local in the app until "Save"; categories and "Take free copies" save immediately; the tournament panel only links to the tournament pages; YDKE copy is computed client-side.

## Database conventions (`migrations/0002_ygo_schema.sql`)

- Primary keys are the Django pks, imported verbatim.
- Money (`price`, `no_card_price`, `amount`) is **TEXT**, never REAL (Django `DecimalField`). Read/write it as `db::Money` / `rust_decimal::Decimal`; never `SUM()`/`MIN()` it in SQL.
- Dates are ISO `YYYY-MM-DD` TEXT. Booleans are INTEGER 0/1.
- Django M2M → join tables `card_category_condition`; the deck zones' `deck_version_{main,extra,side}_deck` became lists in 0027.
- Django MTI `CardConditionalCategory(CardCategory)` → **flattened** into `card_category` with nullable `condition_description`, `categorie_true_id`, `categorie_false_id`. "Is conditional" = `condition_description IS NOT NULL`.
- `card.rarity` (0004): the label of `yugioh_domain::rarity::Rarity` (`Ultra Rare`), NULL when unknown; no CHECK, the forms validate against `Rarity::ALL`.
- `advent_calendar.lot_id` (0006): the calendar's own lot (created from its edit page, `POST /advent-calendar/:year/lot`), NULL when none.
- `lot.refund` (0016): money the seller gave back (Dateacard refunds the shipping), `'0.00'` when none; a lot's cost is `price - refund` (budget, valuation), `price` stays what was paid.
- Books (0007): `book` (`isbn` = ISBN-13 digits, UNIQUE: one row per edition/format; nullable), `book_author` (`sort_name` surname first), `book_book_author` (ordered by `position`), `book_series`, `book_data` (ISBN lookup cache: JSON of `books_domain::book::BookInfo`, NULL = nothing found, asked again after 7 days), `book_advent_calendar[_entry]` (own tables, not shared with the card calendars). **Books can be deleted** (unlike cards); authors/series without books are deleted with them.
- `card_price` (0008): ygoprodeck's market price per `(card_data_id, date)`, weekly, never pruned; `cardmarket_price` EUR (used), `tcgplayer_price` USD (kept for later), NULL = none (`"0"` too). Totals are never stored: computed from these rows and the lot dates (`yugioh_domain::valuation`).
- Cardmarket (0009): `cardmarket_expansion` (set code → idExpansion, NULL = not found), `cardmarket_product` (products named like our card data, latest prices), `cardmarket_price` (history of the linked products), `card.cardmarket_product_id` + `card.cardmarket_product_manual` (1 = chosen on the edit page, kept by the refreshes). Never store the downloaded files.
- Built decks (0010): `deck_version.is_built` (the version holds copies: `deck_version_copy`, 0027), `deck_box`, `sleeves` (free text, NULL when not noted).
- Deck lists (0027): `deck_version_card` (a version's lines: zone, `card_data_id` or a name, `count`, `position`; the shape of `deck_snapshot_card`), `deck_version_copy` (a built version's slots: `card_id` NULL = missing; unique `card_id`: a copy in one built version), `deck_version.is_planned` (on the shopping list), `card_category_assignment.card_data_id` (was `card_id`: a card of a version, all its copies). No proxy `card` rows: `card.is_proxy` is always 0 (drop it in a later migration). Owned / free / missing are worked out (`yugioh_domain::ownership`, `store/lists.rs`).
- `deck_version.is_public` (0018; replaced 0017's `deck.is_public`): the version shown on the public site (the builder's Settings); building a version turns it on (0026 did it for the versions built before), hiding it by hand afterwards sticks. Since 0025 a tournament makes its snapshot public, not the version; a deck is public when one of its versions is: `routes::decks::{PUBLIC_DECK, PUBLIC_VERSION}`, the other decks and versions answer 404 in the copy.
- Tournaments (0011): `tournament` + `placement`/`players`/`conclusion`/`is_team` (`notes` = the old free text, kept until cleared), `tournament_round` (result `win`/`loss`/`double_loss`/`bye`/`forfeit_win`, no drawn rounds), `tournament_game` (`won`/`lost`/`draw`/`unfinished`, any number), `deck_label` (UNIQUE NOCASE) with `deck_deck_label` and `tournament_round_label`. The list played: a `deck_snapshot` with its `tournament_id` (0025; was `deck_version.tournament_id`).
- Pokémon (0012): `pokemon_card` (TCGdex's cards owned or wished, UNIQUE `(catalogue, tcgdex_id)`, `catalogue` `intl`/`ja`: a copy's language `ja` ⇔ the Japanese catalogue; asked again after 30 days), `pokemon_copy` (never deleted: `sold_on`/`sold_price`; `source` booster/single/gift/trade/other; graded: `grader`, `grade`, `cert_number`, `estimate` typed by hand), `pokemon_wish` (`got_copy_id`), `pokemon_price` (`prices` JSON per variant per date, never pruned), `pokemon_set` (set cache by printed code, 7 days; several sets can share a code: 30C), `pokemon_opening` (0013: booster openings, `pokemon_copy.opening_id`; its language and date are its cards'), `pokemon_card.cardmarket_expansion` + `pokemon_booster` (0028: the wishlist's booster suggestions, Cardmarket's booster of each expansion, latest price), `pokemon_card.image_from` (0014/0015: where a picture TCGdex lacks comes from, `pokemontcg:<id>` (the Pokémon TCG API, `pokemon/src/store/ptcgio.rs`), `''` = none found, NULL = not looked up). A card nobody owns or wishes is deleted (`cards::delete_orphans`). Never call TCGdex inside a write transaction; tests insert these rows.
- `yugipedia_errata` (0024): a card data's English text versions from Yugipedia's `Card Errata:<name>` (JSON of `errata::TextVersion`, oldest first), NULL = none, asked again after 90 days. `store/errata.rs` judges a version's missing cards and a built version's wrong-text copies at its format's cutoff, else its ban list's date: `/decks/shopping` and the deck builder's `…/check` (`errata`, `errata_pending`); tests insert these rows: never call Yugipedia from a test (`spawn_errata` does nothing under `cfg(test)`).
- `card.picture` (0019): a Yugipedia file name, NULL = ygoprodeck's picture; `card.picture_manual` 1 = chosen on the edit page (the automatic lookups leave it). `yugipedia_gallery`: a card data's gallery file names (JSON), NULL = no gallery, asked again after 30 days. Tests insert these rows: never call Yugipedia from a test.
- Formats (0022): `deck_format` (`name`, `version` ≥ 1, UNIQUE together; `cutoff` date; `based_on` the Konami list copied), `deck_format_entry` (its list), `deck_version.format_id` (a version plays a ban list or a format, never both), `ygo_set` (every set's TCG date from ygoprodeck's `cardsets.php`, names HTML-decoded: a card's first release = the earliest date of its card data's `card_sets`). Tests insert `ygo_set` rows: `/formats/add` asks ygoprodeck only when the table is empty.
- `book.is_read` (0020): read or not, 0/1, public (the public copy shows a ✓ and its random pick uses it). 0021 forgot the cached "no catalogue knows it" answers (`book_data.json_data` NULL) when the BnF and the Google key came.
- `book.is_private` (0023): 1 = kept off the public copy (the form's switch, a 🔒 in the app). Every book query of the pages adds `books::routes::shown_books()`.
- `card_translation` (0005): ygoprodeck card names in other languages by `(ygopro_id, language)`, a cache: a name found is kept, `name` NULL = no translation on `checked_at`, asked again after 7 days (`card_data::translated_name`). Never ask ygoprodeck for a translation without it.
- Domain names are kept from Django (some French): `unite` (one card in a lot), `apport` (one-off budget contribution), `categorie_true/false`.
- `0002` mirrors Django's constraints (UNIQUE, CHECK on choice fields, nullability, ON DELETE; PROTECT → RESTRICT). Empty Django FileFields (`""`) are imported as NULL.
- Deck history (0025): `deck_snapshot` (a deck's saved lists: `version_id` SET NULL, `created_at` local `YYYY-MM-DD HH:MM:SS`, `name` NULL = automatic, `tournament_id` UNIQUE = the list played there (replaces `deck_version.tournament_id`, NULL and unused since), `is_public`) + `deck_snapshot_card` (zone, card data or name, count, position). Written by `store::snapshots::record` on every zones save (rules: `yugioh_domain::deck_history`); never by copy, so no proxies or locks.
- `sqlx::migrate!` checksums applied migrations. Cutover is done: **never edit an existing migration**, only add new numbered files (next: `0029_…sql`). They run on the NAS's database when it starts the next build of `main`.
- sqlx 0.7 + SQLite concurrency (see `common/src/db.rs`): write transactions start with `db::begin_write(&pool)`, never `pool.begin()`; never `INSERT … RETURNING` + `fetch_one` (not committed until the statement is reset) — use `execute()?.last_insert_rowid()`. Do network calls (ygoprodeck, Open Library) **before** opening a write transaction: they write card data through the pool.
- SQLite + FKs: never drop/rebuild a parent table in a migration while `foreign_keys` is on — `DROP TABLE` fires ON DELETE CASCADE in children.

## Privacy rule: shipment PDFs

Cardmarket shipment PDFs (uploads, `data/media/shipment_files/`, and the test PDFs in `my_ygo_cards/tests/doc/` at tag `django-final`) contain **personal data** (names, addresses).
- Never store their extracted text anywhere: not in the DB, logs/tracing, error messages, test fixtures, snapshots, docs, commits, or Claude memory. Only the parsed fields the app needs (dates, total, seller name, card lines) may be persisted.
- Parse the text in memory and drop it. Tests must read the PDF at runtime and assert on parsed fields; never paste PDF text into source files. Unit tests use synthetic text.
- Use `lopdf` for extraction: `pdf-extract` `println!`s text fragments to stdout. Check any new PDF crate for prints/logs of content.
- To debug the layout, print a masked shape (letters → `a`, digits → `9`), never the text.
- Don't print or quote PDF contents in chat/terminal output, and don't copy the PDFs to new locations without asking.

## Working conventions

- Handlers return `AppResult<T>`; use `?` and `.or_404()`, never `.unwrap()` on DB results. API input errors: `bad_request(...)` (JSON `{"error": …}`).
- New behaviour goes where it belongs: pure logic in the collection's `*-domain` crate, card-row writes in `crates/yugioh/src/store/cards.rs`, ygoprodeck in `yugioh/src/store/card_data/`, pages/handlers in `routes/<area>/` of the collection's crate; what two collections need, once, in `common` (or `common-domain`, `advent`).
- Tests: pure logic as unit tests in the domain crates; handlers and commands through each crate's `crate::tests::TestApp` (a wrapper of `common::testing::TestApp`; pre-insert any card data so nothing hits the network).
- Frontend (`frontend/`): **4-space indentation and airy code** (blank lines between logical blocks, after guards/early returns, around try/catch); `.editorconfig` sets it. TypeScript, strict: props and events typed (`createEventDispatcher<{…}>()`), the API's types imported from `api-types/` (`import type`), a request body tied to its input type with `satisfies`.
- **A deck builder API struct changed** (field added, renamed): `cargo test` rewrites `frontend/src/api-types/`; commit them with the change (the CI fails when they are stale), then `npm run check` shows what the builder must follow. A new struct the builder reads: `#[derive(TS)] #[ts(export)]` (`Money`: `#[ts(type = "string")]`; an input's optional fields: `#[ts(optional_fields)]`).
- **Page scripts** (`static/js/`): plain JavaScript, never built; JSDoc for the checker (`/** @type {HTMLInputElement} */ (document.getElementById('…'))`, `| null` where the code checks; `@param`/`@returns` where it helps). What one script gives another (the rarity data…) is declared in `frontend/static-globals.d.ts`. `npm run check` must stay at 0 errors.
- **The public copy** saves the pages listed in `backend/src/commands/export.rs` (`START`, `public()`): anything private in their templates (and the shared partials they use) goes inside `{% if !common::export::public_copy() %}`; sellers, lots, shipment PDFs, prices paid, notes, ISBNs, tournaments' old notes and forms, private decks and books never in the copy (`backend/src/tests/export.rs`).
- **A deletion:** `data-confirm="…"` on its form (`static/js/confirm.js`, loaded on every page); never `onclick="return confirm(…)"`, which the CSP blocks (the delete then happens without asking). On an edit page it goes in a folded `<details class="danger-zone">` well below "Save" (`static/css/form.css`); a page's own Edit button never has Delete next to it.
- **Dates on the pages**: always `|date` (dd/mm/yyyy, `common::web::filters`), `french_date` in Rust-built text, `frenchDate` in the deck builder; ISO everywhere else (DB, URLs, `<input type="date">`, a sortable cell's `data-sort-value="{{ iso }}"`). Month names (`October 2026`) stay words.
- Askama quirks: template method arguments are passed inconsistently by value/reference — prefer argument-less helper methods (`page.next_href()`); `{% let x = field %}` moves, so expose `&` getters for non-Copy fields.
- Format on save is on (rustfmt via rust-analyzer); keep clippy clean.
- Idiomatic Rust is preferred over strict Django parity (enums, `Result` instead of crashes, fixing Django bugs); note each deliberate difference in the module's doc comment. Clean up code freely while working.
